# 자동 편성 판정 체계

엔진(`gameBoard.service.ts`·`suggest.algorithm.ts`)을 고칠 때마다 같은 기준으로 "배포해도 되는가"를 정한다.
모든 기준을 다 만족시킬 수는 없으므로 **우선순위를 정하고 위 단계부터 본다.**

| 단계 | 무엇 | 지표 | 판정 |
|---|---|---|---|
| 0 절대 규칙 | 어기면 안 됨 | 못 칠 사람 투입, 떼기 요청 어김 | 1건이라도 늘면 보류 |
| 1 공정 | 기다림·판수 | 30분+ 있었는데 0판, 쉬던 사람 두고 연속, 최장 대기, 판수 공평 | 나빠지면 보류 |
| 2 판 품질 | 실력이 맞는 판 | 팀 힘 차이 2+, 같은 성별 3단계+ | 나빠지면 보류 |
| 3 다양성 | 같은 사람 반복 | 같은 4명 다시, 같은 짝 하루 3번+, 혼복 몰린 사람 | 위가 안 나빠질 때만 좋아짐으로 인정 |

- 같은 시나리오를 수정 전·후로 돌려 **시나리오마다 짝지어** 비교한다(차이의 평균과 95% 구간).
  구간이 0을 걸치면 출렁임(차이 없음), 넘어가면 진짜 변화. 아주 작은 변화(지표별 최소 크기 미만)는 무시.
- 전체가 괜찮아도 **조건 하나**(규모·여자 비율·급수 분포·설정·오고 가기, 표본 15개 이상)에서
  0~2단계가 실질 차이의 2배 넘게 나빠지면 보류.
- 결과: **채택**(위는 그대로, 아래가 좋아짐) / **보류**(위 단계가 나빠짐) / **판단 보류**(뚜렷한 이득 없음).

## 돌리는 법

필요: 로컬 DB(docker `badminton-db`) + 시뮬레이션 모임(`시뮬 모임 1~40`, 운영자 01000000002가 대표).

```bash
# 시나리오 몇 개(기본 8개 상황, 빠른 확인)
node scripts/match-eval/run.js --seeds 1,2

# 시나리오 은행(수백 개) — 서버 하나에 동시 4개
node scripts/match-eval/bank.js <bank.json> --par 4 --out 결과.json

# 서버 여러 개로 나눠(코드 감시 없는 서버를 포트별로 띄우고, DB 연결은 서버당 4개로 제한)
API=http://localhost:3200/api/v1 node scripts/match-eval/bank.js <bank.json> --shard 0/5 --par 4 --slot-base 0 --out a0.json
#   …shard 1/5~4/5 는 다른 포트·slot-base 4,8,12,16
node scripts/match-eval/bank.js --from a0.json,a1.json,…   # 합쳐 요약(조건별 약점 지도)

# 판정 — 전·후 결과
node scripts/match-eval/judge.js 전0.json,전1.json,… 후0.json,후1.json,…
```

- 수정 전 엔진은 `git worktree add .wt-base HEAD`로 따로 띄워 같은 시나리오를 동시에 돌린다(지금 작업 트리는 수정 후).
- 시나리오 은행: 운영 정모의 출석 구성(성별·급수·도착/퇴장 분, 이름 없음) + 조건 격자
  (인원·코트 8가지 × 여자 비율 0/20/40/60% × 급수 분포 6가지 × 설정 5가지 × 오고 가기 3가지에서 고르게 240개).
  운영 데이터 기반이라 저장소에는 넣지 않는다.
